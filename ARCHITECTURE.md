# SOMA-BENCH architecture

## What is being measured

The bench answers one question per experiment: *what does a context-engine
variant change about an autonomous agent's real work?* Four observables:

1. **Weighted tokens** (billing proxy, Dendrite spec): `input×1.0 + cache_read×0.1 + output×3.0`
2. **Task success** — SWE-style probes: patch diff vs pristine, test command, needle recall (trajectory-wide, not final-answer-only)
3. **Resident history chars** — persisted `messages.content` totals per arm-run
4. **Wall clock** per run

Token truth is **provider-reported** (read-only from the arm's `state.db`,
tables `sessions` / `session_model_usage`), never estimated. Estimator-based
numbers (chars/4) appear only in engine-internal accounting and are labeled as
ratio-grade.

## The arm model

An **arm** = one Hermes agent configuration, fully matched except the context
engine:

```
~/git/SOMA-BENCH/
  engines/
    somabench/     byte-verified copy of the live SOMA plugin (arm: soma)
    somaguard/     live copy + marginal-guard patch        (arm: soma-guard)
    somaage/       live copy + age-tier patch              (arm: soma-age)
    somatok/       live copy + token-ladder patch          (arm: soma-tok)
    soma16k/       live copy + flat-16K-cap patch          (arm: soma-16k)
  profiles/
    <arm>/         scratch HERMES_HOME: config.yaml, state.db, empty skills/,
                   .env -> symlink to the live secrets file (read-only use)
  tasks/           task specs incl. answer keys (git-ignored, local only)
  runs/<tag>/      run.json, rows.jsonl, per-run records (git-ignored raw;
                   sanitized CSVs in results/ are the public artifacts)
  soma_bench/      the harness (orchestrate, runner, verify, scoring, arm_setup)
  tools/           result-sheet builder, aux scripts
```

- **Engine loading:** Hermes loads context engines from its install tree by
  directory name. The bench adds symlinks
  `~/.hermes/hermes-agent/plugins/context_engine/<dirname> -> engines/<dirname>`.
  The live `soma` entry is never touched; bench arms use separate names.
- **Arm configs are generated** from the live config at setup time (model,
  provider, reasoning, toolsets, max_turns all lifted), so both arms always
  match the host instance. Only `context.engine` differs. Credentials are
  referenced by env-var name; the arm `.env` is a symlink to the live one.
- **Patched variants are derived, never hand-edited:** each is rebuilt at setup
  from a fresh copy of the live plugin + its patch (`soma_bench/patches/*.patch`,
  generated by `gen_*_py` scripts with anchor assertions). A drifted patch
  fails setup loudly instead of producing a silently wrong engine.

## Execution flow

```
orchestrate run -t <task> --arms a,b --repeats N --tag T
  └─ for each task × repeat × arm:
       runner.run_task()
         - fresh workdir in /tmp (mkdtemp) — outside the bench tree so agents
           cannot grep other runs' files (cross-run contamination killed once,
           fixed 2026-09: workdirs used to live under runs/)
         - materialize task workspace (repo copy or synthetic tree)
         - hermes chat --query-file <prompt> --format stream-json
           under env: HERMES_HOME=profiles/<arm>, whitelisted rest
         - stream-json events parsed; session_id extracted
         - usage read from profiles/<arm>/state.db (read-only)
       verify.verify_task()
         - patch probe / test command / trajectory-wide needles
  └─ orchestrate score T  -> summary.json (per-task per-arm averages,
     deltas, Dendrite r-based scores per variant arm)
```

Manual commands: `setup` (build engines + arm homes), `verify` (integrity:
engine copies byte-identical to live, symlinks correct, arms configured),
`tasks` (list), `reverify` (re-run probes over stored records — zero API cost),
`report`.

## Task format (`tasks/*.json`)

SWE-bench-style, self-contained:

- `prompt` — the task as the agent sees it
- `files` / `repo_copy` / `generate_log` — how the workspace is materialized
- `verify_patch` — expected changed files (the "fix")
- `test_command` — must exit 0 with the expected output
- `needles` — facts that must appear in the agent's *trajectory* (not just
  final answer); trajectory-wide checks catch "resolved but never actually
  looked" false passes
- `repeats` — default repeat count

Design regimes: 001 small-result parity, 002/003 static oversized (dodge-risk
probes), 004 runtime-produced oversized terminal output (the true SOMA
regime — ungreppable in advance, re-sent across turns), 005 mega-line
marginal shape, 006 long multi-phase session with cross-phase recall audit.

## Scoring (Dendrite port, `soma_bench/scoring.py`)

- weighted tokens: in×1.0 + cache_read×0.1 + out×3.0
- r = clamp(log2(T_baseline / T_miner)) per task
- zones: penalty below −0.3, maintain −0.3…+0.3, bonus above
- hard-task boost pool; final normalization maps raw [−4,3] → [−1,1]
- baseline arm = no-SOMA (built-in compressor); each variant arm additionally
  scored vs the soma arm directly
- 23/23 unit checks against the published spec

## Evidence discipline

- Excluded runs are documented, not deleted (`excluded=yes` in results CSVs;
  reasons in REPORT files). Invalid runs (patch bug, harness defect) are
  archived under their tag with a root-cause note.
- Per-run contamination checks: grep-dodge (did oversized results actually
  enter context?), /tmp dumping, cross-run file reach (fixed structurally).
- Single-run variance on this model is ±20–30%; conclusions require
  consistent direction across repeats.
